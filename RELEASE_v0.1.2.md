# WorldGen v0.1.2 — Refinement release

This is a single commit on top of WorldGen v0.1.1. No changes to AppLauncher or Ciyan are required: WorldGen's existing launcher packaging contract is unchanged.

## Improvements

- **Area-correct ocean coverage:** new stage-4 generation uses actual Voronoi polygon area to select sea level rather than treating every cell as equally sized. Stage 4 exposes geographic land coverage and per-cell coverage separately. Existing saved coastlines are never regenerated by migration.
- **Explore with measurements:** an optional two-tap distance ruler in world units, including horizontal and vertical offset; tap a third point to measure a new segment. Pan and zoom remain available.
- **Jump to a cell:** enter a cell number to center and highlight its polygon, with its stage-appropriate inspector.
- **Faster map redraws:** reusable polygon paths, exact bounding-box culling, and cached fill colors reduce work during pan and zoom.
- **Stage-aware export:** export a self-contained world through the selected layer, or explicitly export all current layers. Saving checkpoints still works as before.
- **Settings reset:** restore the current unlocked layer's default parameters without affecting locked predecessors.
- **Safer import validation:** reject damaged plate or landform arrays and constrain malformed working-stage input values before scheduling generation.

## Compatibility

- Both `dist/worldgen` and `dist/standalone` still build from `python3 package.py`.
- IndexedDB database `worldgen-v1` and save `schema: 1` are unchanged. Existing v0.1.0/v0.1.1 worlds and checkpoints remain supported.
- Stage 5 landform refinements continue to preserve the locked stage-4 coast mask.
- Future stages 6–12 remain placeholders; this version is still CPU-based, not WebGPU-accelerated.

## Verification

Run `npm test` and `python3 package.py` after applying this patch. Import an older checkpoint or refresh your launcher once to load the new module.
